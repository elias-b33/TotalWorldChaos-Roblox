# Testing in Roblox Studio

How to open the game in Studio, which settings it needs, and a short recipe for checking each feature. Everything here was also played headlessly (`tools/harness`), but rendering, input, sounds, teleports and purchases only really run in Studio.

## Open the project

1. Install [Rojo](https://rojo.space) 7.7 and its Studio plugin.
2. Either:
   - **Live sync:** run `rojo serve` in the repository, open a Baseplate in Studio, and press Connect in the Rojo plugin. Code changes sync while you test.
   - **A place file:** run `mkdir -p build && rojo build -o build/game.rbxlx` and open `build/game.rbxlx`.

## Start here: the first session

A short path through the whole game, in this order (each step names the recipe below with the details):

1. **Build and open.** `mkdir -p build && rojo build -o build/game.rbxlx` and open `build/game.rbxlx` (or `rojo serve` and Connect). Test tab → Device → a phone in landscape.
2. **A solo match.** Workspace attribute `SkipLobby` = true, then Play: you and 9 bots. Watch the Output window: no red errors. Tap your capital (or your nation's button with its flag, top left), press Develop and the troop buttons; tap your army, Move, a target, Go. ("A solo match", "Races and troops", "UI kit and pixel icons".)
3. **Zoom.** Pinch or scroll in on a coast: after a moment the close-up layer paints beaches, surf, trees and crisp borders; zoom all the way out and it goes away. ("Map close-up", "Map labels and badges".)
4. **War and powers.** On the server's Workspace set `DevTick` = 179 (War in a second) and `DevCharges` = 5. Declare war on a neighbour and march in: the battle, the siege pill, the capture. Press the purple power button and cast Meteor. ("War and battles", "Primordial powers".)
5. **The end of a match.** Jump `DevTick` 250, 500, 750, 1000, 1250, 1499 with an order after each (one big jump counts as AFK and pays nothing). Results shows the standings, XP, Glory, quests and achievements. ("Cataclysm and Results".)
6. **The start menu and the Lobby.** Remove `SkipLobby` and Play again: the start menu (Play online, Singleplayer, How to play); Play online, then you pick the first match's map alone (no vote), the draft (each nation's race and bonus), then the match. The next match starts with the map vote. The round buttons bottom left open the shop, quests, trophies and the season pass. ("Start menu and first pick", "Map vote and draft", "Shop", "Quests, calendar, streak", "Achievements", "Season pass".)
7. **Two players.** Test tab → Clients and Servers → 2 players: Play online on both (the first picks the map, the other watches them pick), draft, play, declare war on each other. ("Start menu and first pick", "Map vote and draft".)
8. **Tutorial.** Workspace attribute `Tutorial` = true, Play solo, follow the six prompts. ("Tutorial".)
9. **Sandbox.** Workspace attribute `Sandbox` = `earth`, Play solo: take over a nation, cast free powers, pause and 4×. ("Sandbox".)
10. **Saves.** Turn on Enable Studio Access to API Services, finish a match (step 5), stop, Play again: your level and Glory are still there. ("Saving".)

If something looks wrong, the line from the Output window and a screenshot are the most useful things to bring back to a Claude session.

## Settings

Game Settings → Security (some of these need the place published once):

| Setting | Why |
| --- | --- |
| Allow Mesh / Image APIs | The map art, its close-up layer, the vote thumbnails and the pixel icons are `EditableImage`s, which Roblox blocks in a published game until this is on (Experience Settings → Security, or the Creator Dashboard). Without it the game still works: the map shows names and tokens on a plain background with a "Map art is off" notice, and the icons show as emoji. Studio test sessions create these images without it. |
| Enable Studio Access to API Services | Optional. Real saves (XP, Glory, items) in Studio. Without it ProfileStore uses an in-memory store: everything works and nothing is kept. With it, Studio saves go to their own DataStore (`PlayerData_Studio`), never the live `PlayerData`, and the leaderboards to `Conquest_Studio` and `Level_Studio`: free test purchases and test history stay in Studio, and Studio starts from a fresh save. |

## Test switches (Workspace attributes)

Select Workspace in the Explorer and add attributes in the Properties window.

| Attribute | Type | Effect |
| --- | --- | --- |
| `SkipLobby` | boolean | Matches start straight in Peace (no start menu, map vote or draft) and restart on the same map. Handy for solo tests. |
| `Menu` | boolean | The start menu for arriving players. Unset: on unless `SkipLobby` is set. `true`: on even with `SkipLobby` (arrive in a running match). `false`: off, players join on arrival and the first match votes like the others (the old flow; the harness boots with this). |
| `MapId` | string | Locks the map: `earth`, `eldmoor` or `skyshards`. |
| `Theme` | string | Forces a map theme and skips the theme vote: `theme_night`, `theme_winter`, `theme_autumn`, or `theme_classic` for the classic look (what the private-server setting will do). |
| `Tutorial` | boolean | This server plays the tutorial match (in a live game, new players are teleported to one). |
| `Sandbox` | boolean or string | This server plays the singleplayer sandbox (in a live game, Singleplayer teleports the player to a reserved server of their own): `true` for the default map (or `MapId`'s), or a map id (`earth`, `eldmoor`, `skyshards`). Set it before you press Play; it wins over `Tutorial`. |
| `TelemetryLog` | boolean | Prints every analytics event as `[telemetry] …` in the Output. AnalyticsService only accepts events from a published game, so this is how to check them in Studio. |
| `PrivateServerOwner` | number or boolean | Simulates a private (VIP) server: a userId is its owner, `true` makes the first player in the server the owner. The owner gets a Settings button (gear icon) in the Lobby. In Play solo your userId is your account's; in Clients and Servers the players are -1, -2, … (or use `true`). Don't combine with `SkipLobby` (no Lobby, no settings sheet). |

The test switches below are Studio-only. Set them during a test run on the **server's** Workspace (in Clients and Servers, the Server window). Each is applied once on the next game second and then removed:

| Attribute | Type | Effect |
| --- | --- | --- |
| `DevTick` | number | Sets the match clock in seconds: `179` is War in a second, `1199` the Cataclysm, `1499` the end of the match. A jump counts as time without an order: one of 300 or more makes every player AFK and the match pays nothing ("💤 No reward": no XP, Glory, quests, achievements, season XP or leaderboard points). To finish a match with its rewards, jump in steps under 300 (250, 500, 750, 1000, 1250, 1499) and give an order after each. |
| `DevCharges` | number | Every nation and Primordial gets this many power charges. |
| `DevGold` | number | Every nation with a player gets this much gold. |
| `DevEvent` | number | Every nation's next event card (the EU4 pack, `docs/DESIGN.md` "Events") comes in this many seconds: `0` = on the next game second. An open card stays open. |
| `DevDay` | number | Moves the server's UTC day this many days on (new daily quests, the login calendar and streak, the first-match bonus, the rotating shop, and the season the day falls in). Within 5 seconds everyone gets the new day's quests. `1` = tomorrow; `2` skips a day (the streak's covered missed day). Applied during a match or on Results, not in the Lobby. |
